# 第五部分：全套联调排错优化方案

## 一、常见问题排查

### 1. 定位获取失败

**症状：** 共享端 APP 点击"手动上传"后提示"无法获取定位"

**排查步骤：**
1. 检查手机设置 → 位置信息 → 是否开启
2. 检查 APP 是否被授予"精确位置"权限
   - 设置 → 应用 → 位置共享 → 权限 → 位置 → 选择"使用期间允许"
3. 检查是否在室内（GPS 信号弱）→ 到窗边或室外重试
4. 检查 Google Play Services 是否正常（部分国产 ROM 被禁用）

**代码层面：**
```kotlin
// MainActivity.kt 中的定位获取逻辑
fusedLocationClient.lastLocation.addOnSuccessListener { location ->
    if (location != null) {
        // 成功
    } else {
        // 定位失败，可以尝试触发一次性定位请求
        fusedLocationClient.requestLocationUpdates(locationRequest, callback, looper)
    }
}
```

### 2. 外网无法访问服务器

**症状：** 共享端上传时报错 "Connection refused" 或超时

**排查步骤：**

#### 情况 A：局域网访问不通
1. 确认 Flask 服务器正在运行：`curl http://127.0.0.1:5000/health`
2. 确认手机和电脑在同一 WiFi 下
3. 查看电脑 IP 地址：`ipconfig` (Windows) 或 `ifconfig` (Linux/Mac)
4. 将共享端 APP 中的服务器地址改为 `http://<电脑IP>:5000`
5. 检查防火墙：
   ```bash
   # Ubuntu/Debian
   sudo ufw allow 5000/tcp
   # CentOS/RHEL
   sudo firewall-cmd --add-port=5000/tcp --permanent
   sudo firewall-cmd --reload
   # Windows
   netsh advfirewall firewall add rule name="Flask" dir=in action=allow protocol=tcp localport=5000
   ```

#### 情况 B：外网访问不通（使用 ngrok）
1. 确认 ngrok 正常运行：访问 `http://localhost:4040` 查看 ngrok Web 控制台
2. 确认 ngrok 隧道状态为 "Active"
3. 将共享端和查看端的服务器地址改为 ngrok 提供的 https 地址
4. 如果连接失败，尝试更换 ngrok 区域：`ngrok http 5000 --region eu`

### 3. 网络上传超时

**症状：** 上传请求长时间无响应

**可能原因及解决方案：**
1. **服务器地址错误** → 确认 URL 格式正确（`http://` 或 `https://`）
2. **Token 不一致** → 两端 APP 和服务器的 Token 必须完全相同
3. **网络不稳定** → 切换 WiFi/移动数据测试
4. **服务器负载过高** → 检查 server.py 日志，确认没有大量并发

### 4. 权限申请失败或被系统自动回收

**症状：** APP 运行时定位权限突然消失

**排查步骤：**
1. 某些手机（MIUI、HarmonyOS）会在锁屏后回收后台权限
   - 设置 → 应用管理 → 位置共享 → 权限 → 设为"始终允许"
   - 设置 → 电池 → 省电策略 → 设为"无限制"
2. Android 13+ 需要单独授权通知权限
   - 设置 → 应用 → 位置查看 → 权限 → 通知 → 允许
3. 在 APP 内重新申请：
   ```kotlin
   ActivityCompat.requestPermissions(
       this,
       arrayOf(Manifest.permission.ACCESS_FINE_LOCATION),
       REQUEST_CODE
   )
   ```

### 5. 前台服务被系统杀死

**症状：** 共享开启一段时间后定位停止

**解决方案：**
1. 锁定 APP（防止被清理）：
   - 最近任务 → 长按 APP → 点锁图标
2. 关闭电池优化：
   ```bash
   adb shell dumpsys deviceidle whitelist +com.example.locationshare
   ```
3. MIUI 特殊设置：
   - 设置 → 更多设置 → 开发者选项 → 后台进程限制 → 设为"不限制"
   - 设置 → 应用设置 → 权限管理 → 自动管理 → 关闭"位置共享"

## 二、优化增强

### 1. 请求重试机制

在 OkHttp 中添加拦截器实现自动重试：

```kotlin
// 添加到 OkHttp Builder 中
.interceptor { chain ->
    var response = chain.proceed(chain.request())
    var retryCount = 0
    val maxRetries = 3

    while ((!response.isSuccessful && retryCount < maxRetries) && response.code != 403) {
        retryCount++
        Thread.sleep(1000L * retryCount) // 指数退避
        response = chain.proceed(chain.request())
    }
    response
}
```

### 2. 简易参数加密

对 Token 做 Base64 编码传输（防中间人窥探）：

```python
# server.py 中添加
import base64

def verify_token(token):
    # 同时支持明文和 Base64 编码的 token
    try:
        decoded = base64.b64decode(token).decode()
        if decoded == AUTH_TOKEN:
            return True
    except Exception:
        pass
    return token == AUTH_TOKEN
```

```kotlin
// Android 端发送时
import java.util.Base64
val encodedToken = Base64.getEncoder().encodeToString(token.toByteArray())
```

### 3. 断网缓存优化

完善共享端的离线缓存逻辑：

```kotlin
// LocationShareService.kt 中
private val offlineQueue = mutableListOf<String>()
private val queueLock = Any()

// 上传失败时加入队列
override fun onFailure(call: Call, e: IOException) {
    synchronized(queueLock) {
        offlineQueue.add(jsonPayload)
    }
    Log.w(TAG, "离线缓存: ${offlineQueue.size} 条")
}

// 网络恢复时补发（在上传成功后检查）
private fun flushOfflineQueue(serverUrl: String, token: String) {
    synchronized(queueLock) {
        offlineQueue.forEach { payload ->
            uploadSingle(serverUrl, payload, token)
        }
        offlineQueue.clear()
    }
}
```

### 4. 定位精度优化

```kotlin
// 使用更精确的定位请求
val locationRequest = LocationRequest.Builder(
    Priority.PRIORITY_HIGH_ACCURACY,
    (intervalSec * 1000).toLong()
).apply {
    setMinUpdateIntervalMillis((intervalSec * 500).toLong())
    setWaitForAccurateLocation(true)  // 等待高精度定位
    setMaxUpdates(1)                   // 单次请求只需一次
}.build()

//  fallback：GPS 不可用时使用网络定位
fusedLocationClient.lastLocation.addOnSuccessListener { loc ->
    if (loc != null && loc.accuracy < 100f) {
        // GPS 定位，精度良好
        upload(loc)
    } else {
        // GPS 不可靠，使用网络定位
        val networkReq = LocationRequest.Builder(
            Priority.PRIORITY_BALANCED_POWER_ACCURACY, ...
        ).build()
        fusedLocationClient.requestLocationUpdates(networkReq, ...)
    }
}
```
